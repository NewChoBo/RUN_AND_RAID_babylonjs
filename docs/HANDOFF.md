# 런앤레이드 전용 프로젝트 인계

이 저장소의 `main`에서 Babylon.js 플레이판, 온라인 방 연결, 에셋 도구를 관리한다. 한 단계가 끝날 때마다 동작을 검증하고 목적별로 커밋한 뒤 푸시한다.

## 인계 시점의 상태

2026년 11월 27일 기준으로 전용 경기 이식, 원본 변환, 로컬 에셋 열람, 애니메이션 GLB 등록이 차례로 반영됐다. 마지막 구현 커밋은 `e37f936`이다. 봇 연습은 Photon 없이 실행할 수 있다.

공개 Pages는 `main /`에서 원본 HTML을 서비스하고 있었다. 응답은 200이지만 게임 진입점이 `./src/bootstrap.ts`였다. 저장소의 Actions 변수에도 Photon App ID가 없었다.

## 1. GitHub Pages에 플레이판 배포

1. Pages의 배포 소스를 **GitHub Actions**로 변경한다. `main` 푸시와 수동 실행을 지원하는 워크플로를 구성한다.
2. 깨끗한 체크아웃에서 Node.js 22.12 이상으로 `npm ci`, `npm run check`, `npm test`, `npm run build`를 실행한다. 빌드 단계에 저장소 변수 `VITE_PHOTON_APP_ID`를 전달한다. 변수가 비어 있어도 봇 플레이판을 배포할 수 있다.
3. CI가 만든 `dist/`만 Pages에 게시한다. Vite가 `public/` 전체를 복사하므로 로컬에서 만든 배포본에는 개발진 제공 파일이 들어갈 수 있다. CI 산출물에서 `player-assets/`와 원본 압축 파일이 빠졌는지 검사한다.
4. 실제 [공개 플레이 주소](https://newchobo.github.io/RUN_AND_RAID_babylonjs/)에서 빌드된 JavaScript와 모델이 로드되는지 확인한다. 영웅을 선택하고 봇 연습을 시작해 카운트다운 이후 경기가 진행되는지 확인한다. 배포 실행과 검증한 커밋을 기록한다.

## 2. 새 Photon Realtime 앱 연결

사용자가 [Photon 대시보드](https://dashboard.photonengine.com/en-US/Applications)에서 **Realtime** 앱을 만든다. 리전 허용 목록을 사용한다면 `asia`를 허용한다. 현재 클라이언트는 `src/platform/photon/raid-room.ts`에서 이 리전에 접속하며 앱 버전은 `run-and-raid-11`이다. 방 연결과 이벤트 전송은 Photon이 담당하고 경기 상태는 호스트 클라이언트가 진행한다.

1. 공개 빌드에는 [저장소 Actions 변수](https://github.com/NewChoBo/RUN_AND_RAID_babylonjs/settings/variables/actions)에 `VITE_PHOTON_APP_ID`를 등록한다. 로컬 개발에는 프로젝트 루트의 `.env.local`에 같은 이름을 사용한다. Vite가 웹 클라이언트에 포함하는 값은 Realtime **App ID**다.
2. 변수 등록 후 Pages 워크플로를 다시 실행한다. 이미 배포된 JavaScript에는 새 값이 자동으로 반영되지 않는다.
3. 독립 브라우저 세션 두 개로 공개 주소에 접속한다. 한쪽이 만든 코드 방에 다른 쪽이 참가하고 서로 다른 영웅을 고른다. 두 화면의 경기 시작, 이동·스킬 입력과 그 결과가 양쪽에서 일치하는지 확인한다.

## 후속 개발에서 유지할 기준

UI를 만들거나 변경할 때는 원작 영상·가이드에서 해당 화면의 배치와 조작 순서를 먼저 확인한다. 주 지원 환경은 가로형 모바일 웹이다. 캐릭터·외형·작품은 초상 카드와 큰 선택 버튼으로 열고, 항목이 많으면 목록 안에서 스크롤한다. 터치할 주요 버튼은 가로·세로 44 CSS px 이상을 기준으로 삼고, 작은 가로 화면에서 선택·확정·복귀까지 점검한다. PC에서는 같은 동선을 유지하며 넓은 공간을 활용한다.

모바일 진입 시 바깥 게임 문서에서 가로 잠금을 요청한다. 세로 상태가 유지되면 게임 전체를 회전한 가로 뷰포트에 표시한다. 전체 화면은 설정이나 화면 크기 안내창에서 사용자가 직접 요청할 때 켠다. 로비·대기실·경기는 같은 프레임을 사용한다. 기기를 돌릴 때 경기 상태와 터치 좌표, 브라우저 뒤로가기를 함께 확인한다.

- 규칙과 판정은 `src/game/raid`, 영웅별 정의는 `src/content/raid`, 카메라·모션·효과는 `src/platform/babylon/raid`에서 찾는다. 새 영웅은 기존 영웅별 구현과 스킬 유형 계약을 확장한다.
- 첫 언어는 한국어다. PC와 모바일은 같은 조작 UI를 쓴다. 아날로그 이동 스틱은 터치 지점에서 나타난다. 조준 스킬은 아이콘을 눌러 준비하고, 오른쪽에서 조준한 뒤 손을 떼면 시전한다. 타깃·지점 조준은 사각 트랙패드, 방향 발사는 터치 지점에 나타나는 스틱을 사용한다.
- 평타는 캐릭터 시야를 따르고 타깃 스킬은 카메라 안 적에게 잠긴다. 방향 발사는 궤적을 표시해 예측 사격할 수 있게 한다. 장판은 사거리 안이면 보스 뒤에도 지정할 수 있다. 도약 같은 이동기는 착지점에서 캐릭터의 전방 이동 한계를 지킨다.
- 궁극기 게이지는 0%부터 시작해 준 피해·받은 피해·회복량으로 채우는 것이 이 프로젝트의 설계다. 전투 수치를 조정할 때는 원작 자료에서 확인한 값과 플레이판의 밸런스 결정을 구분한다. 원작 안내의 15%는 이탈에 관한 설명이며, 일반 사망당 보스 추가 피해와 고정 부활 15초는 원작 확정 수치로 취급할 수 없다.
- 개발진 제공 Player 원본 973개를 기준으로 31개 그룹의 FBX, 편집용 Blender 파일과 장면 GLB 876개를 준비했다. 공개 경기용 외형 106종은 상점과 연습 외형 선택에서 불러온다. [원본 변환과 영웅 등록 절차](PLAYER-ASSETS.md)

## 2026-11-27 공개판과 해머 검증 기록

Pages 배포 소스를 GitHub Actions로 전환했다. [검증 커밋 74d4f0d의 배포 실행](https://github.com/NewChoBo/RUN_AND_RAID_babylonjs/actions/runs/45963932071)에서 검사, 테스트 97개, 빌드와 에셋 해시 검사를 통과했다. 공개 브라우저에서 제이드로 봇 경기에 진입했고 남은 시간 2분 25초에 양 팀 마차 피해 15%와 23%를 확인했다. Photon은 Actions 변수 등록 후 재배포와 독립 세션 2개 검증이 남아 있다.

해머·어비스·롱샷·제이드·릴딘·카이켄·스위프트·칼리는 기본 경기 모델에 원작 리그와 게임용 클립 9개가 있다. 원본 ZIP에 대응 모델이 없는 렌드·바스티온·라임은 기존 경기 모델을 사용한다.

## Photon 임시 공용 앱 및 전용 앱 교체

2026-11-27부터 기존 oblivion-archive 웹판과 같은 Photon Realtime 앱을 임시 사용한다. 공개판은 저장소 Actions 변수 `VITE_PHOTON_APP_ID`, 로컬판은 Git에서 제외한 `.env.local`에서 읽는다. 리전은 양쪽 모두 `asia`다. 이 프로젝트의 매칭 버전은 `run-and-raid-11`, 기존 웹판은 `oa-raid-12`여서 매칭 풀은 분리된다.

**남은 작업** — 전용 Realtime 앱을 만든 뒤 이 프로젝트의 Actions 변수와 로컬 값을 새 App ID로 교체한다. Pages 워크플로를 다시 실행하고 독립 브라우저 두 개에서 코드 방 참가, 경기 시작, 이동과 스킬 동기화를 재검증한다.

추격 카메라와 도로 폭을 맞춘 프레임, 화면 좌표와 추정 범위는 [카메라 실측 기록](CAMERA.md)에 있다.
